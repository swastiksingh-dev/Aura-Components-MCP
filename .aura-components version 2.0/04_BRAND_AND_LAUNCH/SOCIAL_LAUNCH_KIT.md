# Social launch kit — v2.0

## Launch message principles

- Lead with the problem solved, not a list of 35+ tools.
- Show one real, impressive, repeatable workflow.
- Include the GitHub link and a short video/demo.
- Mention open-source/free catalogue access accurately.
- Invite developers to try one specific task and report issues.
- Do not promise virality or inflate metrics.

> Aura Components MCP 2.0 is here: move from a design brief to relevant components, purposeful motion and responsive checks — with context-aware MCP workflows.
>
> Open source: [GitHub URL]

## GitHub release notes structure

- Highlights (3–5 concrete capabilities).
- Before/after workflow example.
- New tools and changed tools.
- Removed Inspo tools and migration path.
- Context/output improvements with measured numbers only.
- Compatibility: Node version, client config, MCP behaviour.
- Installation and examples.
- Known limitations.
- Credits and contributors.

## Shareable demo ideas

1. One brief → Design Contract → relevant component search → working page.
2. Same page inspected at 320px and 1440px with a real responsive defect fixed.
3. One hover/scroll interaction observed and rewritten with a purposeful reduced-motion alternative.
4. `aura_diff` comparing two components with actual dependency/feature trade-offs.

## Distribution checklist

- GitHub README/demo and release page.
- X/Twitter launch post and short teaser.
- A concise setup clip or GIF.
- MCP directories/registries only after the tool metadata and setup instructions are stable.
- Ask a few developers to independently install and test; capture real feedback and issues.

A strong release improves the chances of discovery, but no plan can guarantee viral reach. Focus on a clear demo, easy installation, accurate claims and a useful open-source project.
