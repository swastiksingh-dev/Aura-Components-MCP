# Aura Components MCP 2.0 — launch video storyboard

## Purpose

Produce a crisp, real-product launch film for X/Twitter, GitHub and developer communities. The video must show a clear before/after workflow and why v2 is useful. It must not be a generic logo animation with feature claims the product cannot demonstrate.

## Master format

- Target length: 25–35 seconds.
- Master aspect ratio: 16:9, 1920×1080.
- 30 or 60 fps, consistent with the actual screen recordings.
- Separate vertical 9:16 and square 1:1 crops only if all text and UI remain legible.
- Burned-in or sidecar captions; also supply a silent-readable version.
- Keep UI cursor and tool call text readable; zoom/crop instead of showing tiny full-desktop captures.

## Storyboard (30 seconds)

| Time | Visual | On-screen copy | Narration |
|---|---|---|---|
| 0–3s | Rapid but clean montage: raw brief, scattered UI pieces, crowded tool context | `Good interfaces need more than components.` | “A good interface takes more than finding a component.” |
| 3–7s | Real MCP client invokes Aura design planning; Design Contract appears | `Start with intent.` | “Aura turns the brief into a clear design direction.” |
| 7–12s | Actual catalogue search and component comparison; show two options and why one fits | `Find. Compare. Choose.` | “Find relevant building blocks, compare trade-offs, and keep the context focused.” |
| 12–17s | Real implementation screen / resulting page screenshot | `Build with a system.` | “Then build with a coherent visual system.” |
| 17–22s | Actual motion plan / controlled interaction capture | `Motion with purpose.` | “Plan motion around meaning, not decoration.” |
| 22–26s | Multi-viewport screenshots or responsive audit with a real defect and fix | `Verify across screens.` | “Check the result across screen sizes and interactions.” |
| 26–30s | Product name, GitHub repo, install command/QR or short URL | `AURA COMPONENTS MCP 2.0` `Open source · Free catalogue access` | “Aura Components MCP 2.0. Explore it on GitHub.” |

## Recording checklist

- Record the actual tagged/branch build that is being announced.
- Show one end-to-end task, not a fake montage of unrelated features.
- Use a clean demo project and deterministic fixtures.
- Hide private tokens, personal files, terminal history and account data.
- Ensure all text is readable and no cursor obscures important UI.
- Do not speed up tool results so much that they look fabricated.
- Capture at the actual final UI and keep the before/after relationship visible.

## Voiceover tone

Calm, confident, concise developer-product voice. Avoid exaggerated claims such as “revolutionary”, “perfect websites”, “the only MCP you need” or “guaranteed viral”.

## Audio and captions

- Use original or properly licensed music only.
- Add captions that match the spoken narration exactly.
- Include sound effects sparingly and keep voice intelligible.
- Supply a transcript and a no-audio-readable edit.

## Deliverables

- `aura-v2-launch-master.mp4`;
- `aura-v2-launch-vertical.mp4` where practical;
- `aura-v2-launch-captions.srt`;
- voiceover transcript;
- editable project file / timeline / source assets;
- thumbnail frame;
- 5–8 second teaser cut.

If the available coding model cannot render video, it must deliver screen-recording instructions, scene assets, exact timings, voiceover, captions and an editor handoff. It must not create an empty or fake MP4 just to satisfy the filename.
