# README rebuild brief — Aura Components MCP 2.0

## Goal

Rebuild the README as the product's landing page for GitHub. A first-time visitor should understand what Aura does, why it is different, how to install it, and how to see a real result within roughly one minute.

## Suggested top section

1. New banner image (original v2 identity).
2. One-line positioning statement.
3. Small verified badges: npm version, licence, Node requirement, CI, maybe stars/downloads if real.
4. Concise value proposition.
5. A real short demo/video/GIF link.
6. One-command install and minimal client configuration.

Possible positioning line (refine after features ship):

> **Design intelligence for the AI coding workflow — from components to motion-aware, responsive interfaces.**

Do not claim all planned features until they are merged and released.

## Page structure

- What Aura is / who it helps.
- Why it exists and what makes it different.
- Quick start: npm install/command and client configuration, all tested.
- 60-second workflow example: plan → search → compare → scaffold → audit.
- Core capabilities: free catalogue, Design Contract, reference intelligence, motion planning, responsive audit, research cards.
- Example MCP calls with realistic output snippets.
- Tool reference grouped by workflow, not one massive unstructured list.
- Architecture diagram (simple, accurate and maintained).
- Context efficiency and privacy/security notes.
- Browser optionality and known limitations.
- Supported runtime/protocol/client notes.
- Contributing, tests, security reporting, licence and credits.
- Roadmap with shipped vs planned clearly separated.

## README quality rules

- Use current counts only when fetched live or clearly date-stamped.
- Do not use unverifiable performance or token-saving percentages.
- Make installation copyable and put troubleshooting next to setup.
- Keep the tool list collapsible if long.
- Use screenshots of actual Aura workflows and ensure they remain current.
- Add descriptive alt text to all images.
- Check every link, anchor, badge target and npm command.
- Avoid keyword stuffing, empty superlatives and false comparisons.
- Keep both people and coding agents in mind; avoid maintaining a second AI-only README full of duplicated claims.

## README acceptance

A new user can install, connect, make a first call and understand a real end-to-end example without opening source code. All feature claims are verified against the tag being released.
