# Quality, security and compatibility requirements

## Core engineering constraints

- Preserve the free-only access guard and test direct-ID, bundle, scaffold and related access paths.
- Validate tool args at the boundary; keep domain functions deterministic where possible.
- Bound upstream responses, browser capture size, timeouts, retries and local storage.
- Revalidate redirects and destination host/IP policy for URL fetches.
- Do not expose tokens, environment variables, filesystem secrets or arbitrary browser command execution.
- Treat external HTML, JS bundles, package data, research content and site text as untrusted data.
- Keep catalogue and award operations read-only unless a future feature has explicit user-controlled writes.
- Clean up browser sessions, temp files and locks on success and failure.
- Add resource ceilings and graceful unavailable states for optional browser/index features.

## Compatibility

- Preserve CLI binary name unless explicitly changed.
- Document supported Node versions and MCP protocol version.
- Keep public tool names/input schemas stable where possible.
- For breaking tool removals/renames, document the before/after mapping.
- Never silently change the meaning of an existing argument.
- Test exact tool registry consistency and package contents.

## Build and packaging

- Source is authoritative; `dist/` is generated by the build.
- Build must be deterministic and tested.
- `npm pack --dry-run` must include all required runtime files and exclude development-only files.
- Install the generated tarball in a clean temporary project and smoke-test its CLI.
- Confirm zero runtime dependencies by checking package metadata and emitted bundle; don't rely on a README claim.

## Error semantics

Use predictable classes/codes for invalid args, not found, upstream failure, unavailable browser, expired result and resource-limit rejection. Error messages should help the agent recover without leaking private implementation details or stack traces.

## Test matrix

- Input validation: missing, null, wrong type, oversized, unknown enum, boundary values.
- Catalogue: free-only access, Pro refusal, malformed rows, exact match/no match, fallback disclosure, pagination and upstream errors.
- Browser: no browser, bad target, timeout, oversized artifact, cleanup, reduced motion and viewport failures.
- Persistence: corrupt index, schema migration, lock contention, interrupted writes and stale cache.
- Protocol: handshake, tools/list, tools/call, error mapping, deterministic tool order and output schemas.
- Packaging: build, reproducibility, CLI, npm pack, install smoke test.
- Context: output budgets, chunk/cursor continuity, truncation flags and result-handle expiry if implemented.

## Release claims

Do not publish claims like "100% accurate", "perfect responsive", "production-ready for every project" or "viral". Prefer measurable claims tied to tests and a documented benchmark.
